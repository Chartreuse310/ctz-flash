# 数字花园空间框架（定案）

> 取代 [2026-08-05-数字花园框架规划.md](2026-08-05-数字花园框架规划.md) 的方案部分（该文档保留决策过程）。

## 定位

**CTZ's WIKI 的公开数字花园**：一个 Obsidian 仓库即内容源，一个 python 脚本即构建工具，输出纯静态网站。首页是卡片墙，点卡片在模态窗口里阅读（站内不跳转），但每张卡片背后有独立静态页面（SEO 可收录、可分享直达链接）。

与 ctz-wiki 的分工：
- **ctz-wiki** = 全量知识库（00-inbox → 90-logs 严谨消化体系）
- **ctz-flash** = 公开花园（短卡片、闪念、想反复看的内容；每张卡片内容短，可有图片）

## 技术方案

**单脚本静态生成**（介于纯前端 SPA 与完整 SSG 之间）：

- 内容：`notes/*.md`（Obsidian 原生书写）
- 构建：`build.py`（一个 python 脚本，几秒跑完，无第三方依赖或仅 markdown 库）
- 产物：`dist/`（纯静态网站，可直接托管）
- 交互：首页 + 模态窗口为前端 JS 渲染；每张卡片另有预渲染静态 HTML 用于 SEO

为什么不是纯前端 SPA：公开场景需要 SEO、稳定 URL、图片处理，SPA 三项都缺。
为什么不是 Quartz 全家桶：不需要双向图谱/Dataview 等生态集成，一个脚本的成本足够。

## 空间框架

```
ctz-flash/                        # Obsidian vault = 花园本体
├── index.html                    # 花园首页模板（卡片墙 + 模态）
├── assets/
│   ├── garden.css                # 样式
│   └── garden.js                 # 卡片墙渲染 + 模态 + 标签过滤
├── notes/                        # 🌱 卡片目录（Obsidian 里写）
│   ├── attachments/              # 图片等附件（正文引用）
│   └── *.md                      #   每张卡片一个文件
├── discussions/                  # 讨论与规划
├── build.py                      # 构建脚本（生成 dist/）
├── dist/                         # 构建产物（.gitignore，不提交）
└── README.md                     # 仓库说明
```

## 卡片规范

每张卡片一个 md 文件，frontmatter 五个字段（slug 必填）：

```yaml
---
title: 卡片标题
date: 2026-08-05
tags: [主题a, 主题b]
summary: 一句话摘要，显示在卡片墙上
slug: your-card-slug    ← 必填，用于线上 URL
---
```

- **slug**：必填字段，英文小写连字符格式，如 `about-me-smart-mediocrity`。构建时 URL 为 `/notes/{date}-{slug}.html`（如 `2026-08-05-about-me-smart-mediocrity.html`）。不填则构建报错。
- **文件名**：老大在 Obsidian 里自由写（如 `260804 关于我，聪明，和庸才.md`），仅影响 Obsidian 内排序与显示，不影响线上 URL
- **正文**：Obsidian 语法；`[[wiki-link]]` 在模态窗口内可跳转（花园漫游不出站）
- **图片**：放 `notes/attachments/`，正文用相对路径引用；构建时随站点复制
- **内容风格**：短（一段见解 / 一条闪念 / 一个提炼），配图可留白；长文也可
- 构建时 `[[wiki-link]]` 自动转为指向对应卡片静态页的链接

## 站点功能

| 功能 | 实现 |
| --- | --- |
| 首页卡片墙（标题+日期+摘要+标签） | 读取 manifest.json 一次渲染，几百张卡片无压力 |
| 标签过滤 | 点击标签只看该标签卡片 |
| 模态阅读 | 点卡片 → 模态窗口（正文+标签+日期）；`[[链接]]` 模态内切换 |
| 独立卡片页 | `notes/xxx.html` 预渲染静态页，SEO + 直达分享 |
| sitemap.xml | 构建时自动生成，提交搜索引擎 |
| 搜索 | 后续可选（fuse.js 前端模糊搜索） |
| 暗色模式 | 后续可选 |

## 操作方法

### 首次初始化

1. `git init`，创建 `notes/` 与 `notes/attachments/`
2. 写 `build.py`（扫卡片 → manifest → 预渲染 HTML → sitemap → 复制附件）
3. `python3 build.py` 生成 `dist/`
4. 本地预览：`python3 -m http.server 8080 --directory dist`
5. GitHub 建仓库，开启 GitHub Pages 指向部署产物

### 日常流程（加一张卡片）

1. Obsidian 里在 `notes/` 新建 md（按卡片规范写 frontmatter + 正文）
2. `python3 build.py`
3. 本地预览确认效果
4. `git add / commit / push`

### 部署

- 起步：本地跑 `build.py`，产物推 gh-pages 分支（手动，零额外配置）
- 升级：GitHub Actions 里跑 `build.py`，push 自动构建部署（后续做，可先留 TODO）
